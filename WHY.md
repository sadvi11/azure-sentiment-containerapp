# WHY I Built This Project

## The Canadian Business Problem
Canadian enterprises — banks, insurers, and government — run heavily on
**Microsoft Azure**. A team that already has an AI feature on AWS often needs
the same workload on Azure to win an Azure-first client or meet data-residency
rules in `canadacentral`. This project proves I can take an ML service and ship
it to Azure with a full CI/CD pipeline, not just click through the portal.

## Why Azure Container Apps
- **Serverless containers** — no Kubernetes cluster to babysit
- **Scales to zero** — costs nothing when idle, perfect for demos and spiky traffic
- **Built-in HTTPS, autoscaling, and revisions** — production features out of the box

## Multi-Cloud Story
I have the same sentiment API deployed on **AWS EKS** (Kubernetes) and here on
**Azure Container Apps** (serverless). That shows I understand the trade-offs
between clouds and can pick the right tool — exactly what a Cloud/Platform team
wants.

## Nokia Connection
At Nokia I supported carrier systems where automated, repeatable deployments
were non-negotiable. CI/CD on Azure is the same principle: every change is
built, tested, and deployed the same way, every time.

## Target Roles
Cloud Engineer, DevOps Engineer, MLOps Engineer, Platform Engineer (Azure)
